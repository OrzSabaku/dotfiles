# 文書の置き場所

READMEは、自分があとで見返す短いメモにします。
構成、よく使うコマンド、忘れると困る注意を残します。

| 置き場所 | 書くもの |
|---|---|
| ルートREADME | 使っている環境、構成、導入方法、各メモへのリンク |
| 各ディレクトリのREADME | その場所だけに必要な注意や操作 |
| 設定ファイルのコメント | 値や処理を選んだ理由。その設定と一緒に直したいこと |
| Wiki | 詳しい手順、つまずいたときの調べ方、復旧に必要な記録 |
| Git履歴 | 作業の経緯、過去の設定、通常の変更記録 |
| AGENTS.md | エージェントが守る作業上の制約 |

## Wikiの更新

原稿は [wiki/](wiki/Home.md) に置き、GitHub Wikiには同じ内容を掲載します。
修正は原稿側で行います。Wiki上で直接直した場合は、次の更新前に原稿へ戻します。
リモートへの送信は明示的に依頼されたときに行います。現在の原稿は未掲載です。

ページは話題ごとに分け、必要なときだけ追加します。
設定変更で手順が変わったら、該当ページも一緒に直します。
掲載時は`docs/wiki/`内のMarkdownをWikiリポジトリのルートへコピーします。
原稿内のリンクは`.md`付きで書き、掲載時はWikiのページ名に合わせて拡張子を外します。
掲載後に、目次とページ間のリンクが開けることを確認し、「未掲載」の注記を外します。

## メモを増やすとき

- 同じ説明は一か所に書き、ほかからはリンクします。
- 設定値やファイル一覧は原本を参照します。本文に写すのは、理由の説明に必要な範囲に留めます。
- 調査メモは症状・分かったこと・対処を短く残します。未確認のことには確認日と範囲を添えます。
- 完了した移行や一時的な作業結果はREADMEから外します。復旧に必要なバックアップ場所だけWikiに残します。
- アプリやプラグイン自体の説明は、そのリポジトリへリンクします。
- 認証情報や秘密鍵は、READMEにもWikiにも書きません。
